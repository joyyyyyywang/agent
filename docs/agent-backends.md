# 在 Web 中切换 Agent

“Agent”决定谁负责规划和执行工具，“模型”决定本轮使用哪个服务端模型。Web 支持 JoyAgent、Codex、pi 和 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)。外部 Agent 是实际 CLI 子进程，不是更换提示词来模拟。

在同一会话中选择其他 Agent 后，下一条消息交给新 Agent。处理中也可以改选，当前轮仍由发送时选定的 Agent 完成；下一轮使用新选择。浏览器按会话保存 Agent 选择。模型选择仍在当前轮处理期间锁定。

网页加载时以服务端 `/api/backends` 返回的可选 Agent 和默认值更新下拉框，初始页面缺少的选项会补齐。尚未选择过 Agent 的会话使用服务端默认值（当前共享沙箱为 Codex）；已有会话的手动选择继续保留。不可用的 Agent 显示原因，列表读取或校验失败时提示错误，不自动切换执行者。

处理中可新建、切换到其他会话并发送消息，当前轮在原会话继续，结果不会写入另一会话。不同 Agent 可以分别处理请求；同一种外部 Agent 的多个会话在共享进程中排队，等待计入 `turn_timeout_seconds`，没有新进程扩容。同会话禁止重复启动任务，但可发送补充指令；共享 Web 默认每访客最多 4 个在途请求、全局 8 个，排队请求也占用额度。同访客的工作区和长期记忆继续共享。

Web 执行中输入框保持可用，发送按钮改为“补充指令”。JoyAgent 在下一安全步骤读取补充；三种外部 Agent 统一在当前原生轮成功结束后，在同一原生会话续接，当前版本不调用原生的即时中断/steer 接口。即使原生任务还在等待共享进程，也按此时机续接。当前命令不会被强行中止，已经执行的动作不会撤销；处理中改选 Agent 不改变这些补充指令的目标。

补充指令绑定访客、会话和本轮编号，不接受变更模型/Agent；请求编号用于本轮内幂等重试。每轮最多 8 条，累计字符数不超过 `max_input_chars`。续接消耗同一轮剩余模型调用、工具调用和总超时预算；失败或预算耗尽后不重放。界面标记待应用、已应用或未应用，正常结束时保存补充内容和执行结果；尚在内存队列中的补充不能保证跨服务崩溃恢复。SQLite 仍是已保存历史的权威来源。

## 查看运行状态

Web 的“运行中的 Agent”面板显示当前访客、当前工作区中各 Agent 的状态、PID、使用过该 Agent 的会话数及当前原生会话缓存数。展开且页面可见时约每 5 秒刷新，也可手动刷新；收起或切到后台暂停轮询。读取状态不会请求模型或启动 Agent。

“Web 会话总数”包含归档会话，永久删除后扣除，空白新会话也计入。每个 Agent 的“会话数”按实际保存的回复统计；同一对话切换过多个 Agent，会分别计入它们的会话数，因此各行相加可能大于去重后的 Web 总数。“原生会话”是当前常驻进程缓存的数量，进程回收或服务重启后会清零，不表示聊天记录丢失。JoyAgent 使用 SQLite 历史，不占用原生会话缓存。

PID 显示外层沙箱中的 Agent 入口进程编号；无法确认原生进程映射时显示空值，并单独标注管理进程 PID。JoyAgent 与 Web 服务共用 Python 进程，不能把它的 PID 当成独立 CLI 进程。面板是瞬时快照，正在执行、空闲、启动中与未启动分别显示，不通过操作系统进程的睡眠状态推断任务是否完成。共享 Web 的接口 `GET /api/agents/status` 使用现有访客 Cookie、CSRF 和同源校验，不提供其他访客的进程信息。

SQLite 保留统一历史，同一浏览器身份的工作区持续保留。三个外部 Agent 按需启动常驻进程：同一访客、同一工作区、每种 Agent 最多一个进程，首次发送消息时启动，仅在下拉框选择不会启动。多个 Web 会话共享这个进程，各自拥有独立的原生会话 ID 和聊天上下文；同一 Agent 串行处理这些会话的请求。正常回复后保留进程和原生会话，切换回来会补入期间缺失的对话和工具结果，不把已处理历史整段重复发送。

聊天历史默认限制为本次输入及同一会话此前两轮，通过 owner 的 `policy.toml` 中 `[limits].context_turns = 2` 调整；旧配置未写该字段也默认使用 2。`history_messages` 与 `context_chars` 仍可进一步减少历史。本轮从最初输入到工具结果、补充指令的完整执行块保留，不会把每个工具步骤算成一轮，也不读取别的 Web 会话的聊天记录。固定系统规则、工具定义与显式保存的长期偏好独立于这个聊天窗口。

窗口起点发生移动时，仅卸载并重建该会话对应的原生会话，同时清除其模型桥续接缓存；共享进程、其他 Web 会话和工作区继续保留。窗口不变时仍采用原来的增量续接，避免重复发送已处理的消息或重复执行工具。原生会话 ID 因窗口裁剪可能变化，Web 会话 ID 和持久化历史保持不变。外部 CLI 固定提示、缓存命中和网关负载仍影响输入量与响应时间，缩短聊天历史不保证每次响应都更快。

| Agent | 常驻接口 | 原生会话 |
| --- | --- | --- |
| Codex | `app-server` stdio | 每个 Web 会话一个私有持久 thread；用 turn 追加消息 |
| pi | `--mode rpc` | 每个 Web 会话一个原生 session；通过私有会话文件切换 |
| DeepSeek Harness | ACP JSON-RPC | session / prompt |

常驻进程没有固定闲置过期时间。默认整个 Web 事件循环最多保留 8 个，可通过 `backends.resident_limit` 设置为 1–32；满额时回收最久未使用且空闲的进程，全部繁忙时拒绝新启动。每个进程最多缓存 64 个原生会话，达到上限时卸载最久未使用的原生会话，之后可从 SQLite 历史重建。这是缓存容量，不限制用户可以保存的 Web 会话总量，也不会因此删除聊天记录。

已有进程在空闲时异常退出，会依次等待 1、5、15 秒尝试恢复；自上次成功对话起最多自动重启 3 次，成功对话后重新计数。恢复只启动进程，不调用模型或重放工具；原生会话缓存清空，下一条消息从 SQLite 历史续接。恢复沿用原池槽位和 LRU 顺序，不挤占其他访客；服务关闭、容量淘汰及删除清理不会触发恢复。执行中的失败、超时和取消不自动重试。

面板在恢复期间显示“启动中”和恢复提示；达到上限保留“进程异常”，下一条用户消息仍可触发启动。面板和服务日志只记录固定的内存/线程/资源采样/输出/协议/进程退出分类及可确认的整数退出码，不记录原生 stderr 或聊天正文。资源上限继续生效，不能仅凭“进程异常”判断为模型或网络故障。

Web 轮次状态显示“聊天模型请求次数”；失败尝试也计入，不代表工具数量。未完成统一提示“本轮未完成，原因见回复”，不能据此推断调用预算耗尽。原生模型桥区分本地请求并发通道繁忙（`busy`）、上游限流（`rate_limit`）和模型/工具预算耗尽（`budget`）；每次激活只为首次失败记录固定分类与来源，不记录请求内容、URL、凭据或上游错误正文，不自动重跑已执行操作。

归档会保留原生会话，恢复后可继续，但仍受上述缓存容量规则约束。永久删除会卸载并清理各 Agent 中对应的原生会话，再删除 SQLite/JSONL 对话内容；正常情况下保留共享进程和其他 Web 会话的原生上下文。若无法确认单个原生会话已清理，会关闭该 Agent 的共享进程并清空其缓存，其他会话下次使用时从 SQLite 历史重建。访客运行时被淘汰或服务关闭时，也会清理其进程与原生缓存。

原生会话是运行期间可丢弃的缓存，临时文件位于当前访客 `data_dir/native_sessions/`，不保证服务重启后保留原生会话 ID。Codex 使用生成的私有 `CODEX_HOME` 保存 thread，不使用 `ephemeral`，以支持原生 `thread/delete` 删除指定线程；pi 使用私有 `--session-dir`，不使用 `--no-session`，以支持同进程切换独立会话。服务关闭时清理这些缓存，三个 Agent 不读取个人登录、插件或平台 Codex 的会话状态。

单会话删除同时处理对应的大工具输出文件及原生数据库的已删除页和 WAL。Codex 的私有 SQLite 诊断日志禁止写入正文；原生 stderr 有输出上限，不会展示在 Web。清理依赖安装器固定的 CLI 版本，目录被替换、协议或数据库结构不兼容时会拒绝确认并回收该 Agent 缓存。

回收或异常后再次使用会创建新原生会话，并从受预算约束的 SQLite 历史恢复上下文；恢复流程不自动重试上一轮操作。长历史可能被截断，已写入的工作区文件不会回滚。

模型仍按每轮的手动选择或自动路由结果确定，进程复用不会固定为首次使用的模型。本轮的工具循环始终使用同一模型；切换 Agent 后再切回来，只补入该原生会话尚未收到的对话和工具结果。

## 显式安装

普通 JoyAgent CLI/Web 运行时仍只依赖 Python 标准库。三个可选 CLI 使用独立安装目录和锁文件；启动 Web 不会自动安装、更新或登录。

安装机需要可用的 npm。集团网络下执行：

```bash
python3 ops/install_agent_runtimes.py \
  --prefix "$HOME/.local/share/joyagent/agent-runtimes/v1"
```

安装器使用独立 HOME、npm 配置和缓存，依赖版本固定在 `ops/agent-runtimes/package-lock.json`，下载使用集团 npm 镜像。目录已有相同锁文件时校验版本；不同依赖版本需要新的目录。安装后可使用目录下 `bin/codex`、`bin/pi`、`bin/dsh`。这些终端命令独立启动时不自动获得 JoyAgent 的模型配置或模型密钥。

| 组件 | 固定版本 |
| --- | --- |
| Node.js | 24.22.1 |
| Codex | 0.142.5 |
| pi coding agent | 1.3.0 |
| DeepSeek Harness (`dsh`) | 0.2.1-rc.2 |

安装器只运行 `--version` 验证，不生成模型回复，不读取现有个人/平台 Agent 的登录凭据。`pi` Agent 与本项目 TUI 的 `pi-tui` 是两个不同依赖。

## 服务端启用

Web 中执行外部 Agent 要求 Linux、bubblewrap、prlimit 及可用的 user/mount/pid/net namespace。macOS 可以安装 CLI，但当前 Web 外部 Agent 执行器不支持 macOS，不会退回未隔离的宿主执行。

在 owner 管理的配置中，保留现有 `[model]`、`[execution]` 等段并修改相应字段，不要重复定义同一个 TOML 表：

```toml
[execution]
enabled = true
network = "none" # 可显式改为 "host"，共用外层沙箱网络

[backends]
default = "codex"
resident_limit = 8 # 1–32；整个 Web 事件循环的常驻进程总上限
install_dir = "/home/admin/workspace/joyagent/agent-runtimes/v1"

[backends.codex]
enabled = true
[backends.pi]
enabled = true
[backends.deepseek]
enabled = true
```

重启 Web 后，“Agent”下拉框显示已启用的项目。缺少依赖或不支持隔离执行时显示原因，不能静默改用其他 Agent。`default` 必须已启用；JoyAgent 始终可选。

OpenCode 后端已移除。升级旧配置时删除 `[backends.opencode]`，若旧默认值是 `opencode`，须改为已启用的 Agent（共享服务使用 `codex`）。旧浏览器保存的 OpenCode 选择会在打开会话时清除，采用服务端默认 Agent；旧聊天和工具记录保留原 OpenCode 标记，不因移除后端而删除。其他不可用或未识别的已保存 Agent 选择仍须手动更改。

外部 Agent 当前要求 OpenAI Chat 兼容 provider，包括当前 IdeaLab 配置；仍使用服务端 `model.choices` 的模型和凭据。Codex 的 Responses 请求由服务端转换为 Chat 请求，因此不要求当前网关另行提供 Responses API。转换覆盖文字、函数及自定义工具子集，不支持图像、网关侧 `previous_response_id` 持久续接、后台请求或要求特殊推理 continuation 的模式。Codex 常驻 thread 的上下文由原生进程保留，并在请求中提供。模型需要支持工具调用；具体协议兼容性、工具选择与任务完成能力取决于所选模型。

## 权限和执行记录

启用某个外部 backend 表示管理员授权它使用原生文件和命令工具操作浏览器工作区。JoyAgent `policy.tools.allow/deny` 的具体工具名称只约束 JoyAgent 工具；不能用这张名称表细分外部 CLI 内部工具权限。外部 CLI 的限制来自进程隔离、模型请求预算、工作区挂载和 owner 生成的配置。需要更细工具权限时使用 JoyAgent。

外部 CLI 只能写当前访客的工作区和该 Agent 进程的私有临时状态，系统运行库与 CLI 安装目录只读；没有宿主 HOME、其他访客目录、模型密钥、SOUL/policy 源文件或数据库挂载。平台不允许在 namespace 中挂载 procfs，Codex 只获得指向自身程序的静态 `/proc/self/exe` 兼容链接，没有宿主进程信息。原生插件、自动更新及 CLI 自带的额外联网功能仍由适配器关闭。

在网页中生成文件时，请指定 `/workspace` 下的路径，例如“生成查询当前北京时间的 Python 脚本，保存到 `/workspace/testscript/query_date.py`，写完运行一次”。这里的 `/workspace` 是当前访客的持久工作区；执行环境中的 `/home/admin/workspace` 等同名目录不代表宿主目录。适配器会提示先完成最小可用结果、合并必要检查并遵守整轮时间预算，避免在简单文件任务中反复探测未请求的功能。这些执行指引不扩大权限，也不能保证所有模型都在预算内完成。

如果原生 Agent 中断，页面明确显示未收到最终结果，并保留已完成工具记录；中途的“接下来写文件”等过程说明不再作为最终回复。Codex 工具协议转换失败会记录为 `response / protocol`，不记录模型正文、工具参数或凭据。仍需核对工具记录和实际文件，不能以创建目录成功推断脚本已经写出。

三种 Agent 的工具网络统一遵循 owner 配置的 `execution.network`：默认 `"none"` 不提供外网；`"host"` 共用外层沙箱网络及回环端口，并只读使用外层 DNS 配置和 TLS 根证书。host 模式下，原生命令工具可访问外层允许的网络；文件隔离与模型密钥管理不变，不自动继承代理变量或私有凭据。外层 DNS 或出站失败仍会影响内部请求。修改后重启 Web，使常驻进程采用新设置，详细说明见[共享执行配置](deploy-shared-web.md#命令脚本与共享-mcp)。

宿主已安装 GCC/binutils 时，隔离环境提供其系统运行库，以及存在时的固定 `/etc/alternatives/ld`、`as` 只读入口，支持编译、链接和运行 C/C++ 示例；不会挂载整个 `/etc/alternatives` 或 `/etc`。别名目标须为 `/usr` 内 root 所有、不可被组或其他用户修改的普通可执行文件，且不能与工作区或私有配置重叠。缺失的编译器仍需管理员安装。

模型请求通过回环 HTTP 桥和 Unix socket relay 转发，目标地址、模型、token 上限由 owner 配置强制确定。`none` 模式的桥位于隔离环境内；`host` 模式在外层分配独立动态端口。CLI 只持有每进程随机生成的内部鉴权 token，真实模型密钥留在服务端。转发权限按轮次激活并在本轮结束后撤销；空闲进程的模型请求会被拒绝，常驻不会授权后台模型调用。

模型请求数和模型返回的工具调用数沿用 policy 每轮上限，外部进程有轮次超时、输出、地址空间和文件大小限制；单进程地址空间上限为 2 GiB。任务启动时从已有可用 CPU 中选两个设置亲和性，避免 CLI 按宿主全部 CPU 创建庞大的线程池；这不是 CPU 硬配额。宿主每 200ms 采样该任务整个后代树，超过 128 个线程或总 RSS 768 MiB 时终止任务；短时峰值仍可能发生。RLIMIT_NPROC=4096 按真实 UID 计数，包括父 namespace 的其他任务，不是每访客独享配额；较小值会在当前平台导致 CLI 无法创建线程。地址空间与采样限制不能替代进程树的硬内存配额。当前平台未提供可写的 delegated cgroup，不宣称具备每访客 cgroup 内存隔离。

Web 在本轮结束后显示规范化工具记录；不展示原生推理事件或 stderr。回复与工具结果连同 Agent 标记进入统一历史。当前是整轮返回，模型 relay 的 SSE 是缓冲后的协议转换，不是逐 token 推送到浏览器。

执行失败、超时或取消会关闭该 Agent 的共享进程、清理其原生会话缓存并撤销本轮转发权限。该访客使用此 Agent 的其他 Web 会话也会在下次发送时从 SQLite 的有限历史重建，不自动重试本轮。已经送到模型服务的请求可能继续完成和计费，已完成文件操作不会回滚。宿主 relay 全进程最多 32 个连接、8 个模型请求；取消后的在途请求仍占用额度直到真正返回。

`/tools`、`/tool` 显式指令始终使用 JoyAgent 的权限检查。现有 MCP 可从这里直接调用，当前不会自动迁移进三个外部 CLI 的原生 MCP 配置。切回 JoyAgent 可继续由模型选择已授权的 MCP。

python3 -m unittest discover -s tests -v
node --test tests/web_app.test.mjs

# Linux 且已显式安装三个 CLI 时，运行真实 CLI + 假模型的集成验证。
JOYAGENT_TEST_CLI_PREFIX=/home/admin/workspace/joyagent/agent-runtimes/v1 \
  python3 -m unittest discover -s tests -p test_cli_backend.py -v
